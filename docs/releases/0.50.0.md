# 2Hop Links Plus 0.50.0

[日本語](#日本語) | [English](#english)

## 日本語

画像の多い大きな Vault で、メモリと待ち時間を減らすための変更です。

- カードの画像を、元の大きさのまま読み込まず、カードの大きさに縮めた画像（縮小画像）で表示するようにしました。
  ノート内の最初の画像（PNG・JPEG・WebP・BMP、2 MB まで）を一度だけ読み込んで縮め、小さな画像として保ちます。
  縮小画像は一度に一枚ずつ作り、新しいものから 150 枚（iPhone・iPad では 80 枚）まで覚えます。
  表示中のカードの画像は消さず、使われなくなったものから片付け、プラグインを止めるときにすべて片付けます。
- 縮小画像を作れないとき（GIF、読めない形式、機能のない環境）は、これまでどおり元の画像を使います。
  iPhone・iPad では、その場合の元の画像は 512 KB までのものに限り、それより大きい画像は枠ごと出しません。
- ノートの作成・削除・名前の変更のたびに Vault 全体のリンク表を作り直していたのをやめ、
  そのノートと、そのノートの名前へのリンクを持つノートだけを読み直すようにしました。
  フォルダの名前を変えたときだけ、これまでどおり作り直します。
- 計算済みの結果は、変わったノートが関係する結果だけを捨てるようにしました。
  同期で届いたノートや、表示中のノートと関係のない変更では、結果を作り直しません。
  そのセッションで初めて変わったノートは、リンクやタグが実際に変わったときだけ変更として扱います。
- 大きなハブのノートや、起動後最初のリンク表の作成で画面が固まらないよう、
  計算の途中で少しずつ画面に処理を返すようにしました。別のノートに移ると、途中で計算をやめます。
- 別パネル表示で、更新のたびにリンクのクリック処理が積み重なっていたのを直し、パネルに一つだけ付けるようにしました。
- カード検索で本文も探す設定のとき、読んだ本文の控えを端末内（IndexedDB）に残し、
  次に Obsidian を開いたときも使うようにしました。ノートの更新日時と大きさが同じときだけ使います。
  控えは 2,000 件・1,000 万文字までで、古いものから消します。同期はされず、`data.json` にも書きません。
  使えない環境では、これまでどおりメモリ内だけで動きます。
- 設定、関連ノートの並び順、画像の選び方、共通 CSS は変更していません。

確認した範囲はビルド、自動テスト 60 件、コード検査です。自動テストは縮小画像の作成回数・大きさ・片付け、
カードの表示、リンク表の部分更新、結果の残し方、計算の中断、クリック処理の数、本文の控えの使い方を
模擬環境で確かめるものです。実際の画像の縮小、IndexedDB への保存、iPhone・iPad での表示とメモリ、
起動ロゴへ戻る現象の解消は未確認です。

## English

Changes to cut memory use and waits in a large, image-heavy vault.

- Card images are shown as card-sized thumbnails instead of the full image.
  A note's first local image (PNG, JPEG, WebP or BMP, up to 2 MB) is decoded
  once, drawn to cover the card's image box at the device pixel ratio (capped
  at 2) and kept as a small blob URL. Thumbnails are made one at a time and
  the most recent 150 (80 on iPhone/iPad) are kept; ones a card still shows
  are never dropped, and blob URLs are revoked when dropped and on unload.
- When no thumbnail can be made (GIF, an unreadable format or a missing
  browser API), the original image is used as before. On iPhone/iPad that
  fallback is limited to originals up to 512 KB; larger ones show no image.
- Creating, deleting or renaming a note no longer rebuilds the whole link
  index: that note and the notes whose links name it are reread. Only a
  folder rename still rebuilds.
- Cached results are dropped only when the changed note can alter them, so
  notes arriving by sync and changes unrelated to the shown notes keep the
  cache. A note's first change in a session counts only when its links or
  tags actually differ from the index.
- The gather, including the first link-index build, gives the main thread back
  between short slices, so big hub notes do not freeze the UI, and stops at
  the next checkpoint when superseded.
- The side pane no longer adds another click listener on every update; one
  delegated listener is registered when the pane opens.
- With body search on, body texts are also kept per device in IndexedDB and
  reused in later sessions while the note's mtime and size match. The store
  holds at most 2,000 texts and 10 million characters, drops the least
  recently used first, is not synced and is not written to `data.json`.
  Without IndexedDB it quietly stays in memory as before.
- Settings, related-note ordering, image selection and shared CSS are
  unchanged.

Validation covers the build, 60 automated tests and lint. The tests check, in
a simulated environment, thumbnail creation counts, sizes and release, card
rendering, incremental index updates, result-cache eviction, cancellation,
the number of click listeners and use of stored body texts. They do not
verify real image downscaling, IndexedDB storage, iPhone/iPad layout or
memory, or resolution of returns to the app's startup logo.
